## 🎯 一、 代码诊所大排查标准答案（PPT 第7、8、9、10页）

1. `FILE *fp = fopen("C:\\Windows\\system.log", "w"); fputs("System warning!", fp);`
   - **漏洞原因**：
     1. 日志记录误用 `"w"` 模式，导致原有的全部历史系统日志被瞬间抹杀清空；
     2. 缺少 `fp == NULL` 防御检查，若路径无写权限将引发段错误；
     3. 漏写 `fclose(fp)`。
   - **修改方案**：使用 `"a"` 模式，增加 `if (fp == NULL) return;` 并在写完后 `fclose(fp);`。
2. `FILE *fp = fopen("config.ini", "r"); char buf[80]; fgets(buf, 80, fp);`
   - **漏洞原因**：若 `config.ini` 文件不存在，`fopen` 将返回 `NULL`，随后的 `fgets` 试图对空指针进行解引用读写，导致程序闪退崩溃。
   - **修改方案**：增加 `if (fp == NULL) { perror("打开配置失败"); return; }`。
3. `FILE *fp = fopen("data.txt", "w"); fprintf(fp, "Score = 100\n");`
   - **物理灾难后果**：因为缓冲文件系统的存在，写入的数据停留在内存的 512 字节文件缓冲区内。未调用 `fclose()` 且程序结束时，末尾数据可能未被物理冲刷（Flush）至磁盘，导致文件内容丢失或为空！
   - **修改方案**：操作完毕后显式调用 `fclose(fp);`。

## 🧠 二、 打开模式矩阵大考验标准答案（PPT 第8页）

| 打开模式 | 文件已存在时的表现 (保留/抹除) | 文件不存在时的表现 (报错NULL/新建) | 读写权限 (只读/只写/读写/追加) |
|:---:|:---:|:---:|:---:|
| **`"r"`** | 保留原内容 | **报错返回 `NULL`** | 只读 |
| **`"w"`** | **无情抹除原文件并重建** | 新建文件 | 只写 |
| **`"a"`** | **安全保留，光标移至末尾** | 新建文件 | 追加写入 |
| **`"r+"`** | 保留原内容，光标在文件头 | 报错返回 `NULL` | 读写 |
| **`"wb"`** | 无情抹除原文件并重建 | 新建二进制文件 | 二进制只写 |

## ⚔️ 三、 异常防护盾深度辨析标准答案（PPT 第16页）

1. **`feof(FILE *fp)`**：检查文件位置指针是否已穿过文件物理末尾（EOF）。到达末尾返回非 0 值（真），否则返回 0。
2. **`ferror(FILE *fp)`**：检查文件在进行 I/O 操作时是否发生物理硬件级错误（如写保护、磁盘满、拔出设备）。出错返回非 0 值（真），未出错返回 0。
3. **`clearerr(FILE *fp)`**：将指定文件流的错误标志和结束标志强制复位重置为 0。

## 📝 四、 离堂小测标准答案（PPT 第20页）

### Q1. 缓冲文件系统的物理机制
- **正确答案**：**D**
- **解析**：标准 C 采用缓冲文件系统，数据先进入 512 字节内存缓冲区，`fclose()` 会触发关键的强制冲刷（Flush）动作，绝非“关不关无所谓”。

### Q2. 字符读取与 EOF 变量类型
- **正确答案**：**B**
- **解析**：`EOF` 通常为 `-1`，若用 `unsigned char` 接收会被隐式转换为 `255`，使得 `ch != EOF` 永远为真，导致程序陷入死循环。

### Q3. 文件打开模式的安全性
- **正确答案**：**C (`"a"`)**
- **解析**：追加模式 `"a"` 在文件不存在时能自动创建，在文件存在时会将物理光标定位到末尾继续追加，不会破坏以往的交易数据。
