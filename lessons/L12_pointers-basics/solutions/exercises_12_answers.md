## 🎯 一、 代码诊所大排查标准答案（PPT 第6、8、9、10页）

1. `int a = 10; int *p; *p = a;`
   - **错误原因**：指针 `p` 声明后未被赋予合法变量的地址，里面存储的是随机垃圾门牌号（野指针），执行 `*p = a` 会非法侵入系统内存引发段错误崩溃。
   - **修改方案**：在解引用前让指针指向合法变量，即 `p = &a;`。
2. `double x = 3.14; int *p = &x;`
   - **错误原因**：指针类型（`int*`）与目标变量类型（`double`）不兼容，解引用时将发生物理内存字节长度读取错位。
   - **修改方案**：将指针声明为 `double *p = &x;`。
3. `int b = *p++;`
   - **运行结果**：`b = 5`
   - **指针变化**：由于后缀自增 `++` 与 `*` 优先级相同且自右向左结合，`*p++` 等价于 `*(p++)`。先取出 `*p` 的值赋给 `b`，然后指针 `p` 自身的地址值加 4 字节，导致 `p` 不再指向变量 `a`，移到了未知内存单元！若想给值加 1 应写为 `(*p)++`。

## 🧠 二、 swap 三国演义内存栈帧追踪（PPT 第13、14、15页）

- **版本 B (偷梁换柱)**：
  - **a与b最终值**：`a = 5, b = 10` (交换失败)
  - **物理原因**：虽然传递了地址，但函数体内仅执行 `t=p1; p1=p2; p2=t;` 交换了形参指针自身的地址值，自始至终未曾通过 `*` 解引用去触碰主函数栈帧中的变量 `a` 和 `b`。函数退出后形参销毁，主函数变量毫发无损。
- **版本 C (地址传递)**：
  - **a与b最终值**：`a = 10, b = 5` (交换成功)
  - **物理原因**：形参通过 `*p1` 和 `*p2` 解引用直接打开主函数栈帧中 `a` 和 `b` 的大门，原地调换了存储单元中的数值，函数退出后修改永久保留。

## ⚔️ 三、 符号时序对决深度解析（PPT 第8页）

1. `&*p` 等价于 **`&a`**，数据类型为 **`int*`**（整型指针/地址）。
2. `*&a` 等价于 **`a`**，计算结果为 **`100`**。
3. 执行 `(*p) += 10;` 后，变量 `a` 的值变为 **`110`**。

## 📝 四、 离堂小测标准答案（PPT 第19页）

### Q1. 解引用操作对变量物理地址的影响
- **正确答案**：**D**
- **解析**：`*p = 10;` 只是修改了指针所指向的变量 `a` 内部存储的值为 10，指针 `p` 自身的指向与地址值绝对没有发生任何改变。

### Q2. 指针多函数协作黄金三步法则
- **正确答案**：**D**
- **解析**：通过地址传递和 `*` 解引用原地修改后，数据已直接在主调函数内存中生效，无需且不应依赖 `return` 返回。

### Q3. 野指针防护天条
- **正确答案**：**A**
- **解析**：`NULL` 代表 0 号受保护地址；指针未初始化强行解引用会导致崩溃；向 `NULL` 写入会报错；`NULL` 适用于所有类型的指针。
